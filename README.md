# DS_TG_BOT — Discord-бот и панель сообщества

Discord-бот следит за активностью, выполняет правила из веб-панели, запускает споры и раздаёт награды. Telegram-бот остался в проекте, но в обычном деплое не запускается.

## Возможности

- **Сбор статистики**: время в голосовых каналах, сообщения Discord, теги игр, ежедневные и месячные агрегаты.
- **Гибкие правила** через веб-панель: `условие → действие`. Например: «трое определённых людей в голосовом канале → пометить как Valorant и написать в Telegram».
- **Valorant и роли**: после заданного времени пары в одном голосовом канале бот переносит обоих в выбранный канал и временно снимает роли, если у одного отображается Valorant. Время первого и повторного срабатывания, а также срок наказания задаются в панели.
- **Споры**: запуск в Discord (`/dispute`) или через панель, голосование в Discord.
- **Награды месяца**: в конце месяца считаются самые активные участники; результаты доступны в Discord и панели.
- **Красивая веб-панель**: дашборд, редактор правил, споры, упоминания, рейтинг, награды, настройки.

## Архитектура

Монорепа (npm workspaces):

```
packages/
  db/            Prisma-схема + сервисы статистики/наград (PostgreSQL)
  shared/        Общие типы (правила, шаблоны, утилиты)
  discord-bot/   discord.js — трекинг активности, команды, движок правил
  telegram-bot/  grammY — команды, мост сообщений, голосование в спорах
  web/           Next.js — панель управления
```

Связь Discord ↔ Telegram идёт через таблицу `BridgeMessage` в общей БД: Discord-бот пишет события, Telegram-бот их подхватывает.

## Быстрый старт (Docker)

### Деплой с Windows-ПК по SSH — рекомендуемый путь

Нужны VPS с **Ubuntu 22.04 или 24.04**, SSH-доступ и локальная папка проекта на ПК. Скрипт установит Docker, Compose и Buildx на VPS при необходимости. Для Ubuntu 22.04 должны быть включены стандартные репозитории `universe` и `jammy-updates`: в них доступны пакеты Compose v2 и Buildx. На Debian скрипт тоже работает, если Docker Compose v2 и Buildx доступны в пакетных репозиториях или уже установлены. На ПК нужны встроенные `ssh.exe`, `scp.exe` и `tar.exe`; Node.js и Docker на ПК для деплоя не нужны.

Открой PowerShell в корне проекта и выполни:

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy-from-pc.ps1
```

Скрипт по очереди спросит IP или домен VPS, SSH-пользователя и порт, путь к SSH-ключу (если он есть), Discord-токен и ID, пароли БД и панели, порт веб-панели. У каждого вопроса есть пример ввода. При входе по SSH-паролю оставь путь к ключу пустым: пароль запросит `ssh.exe` при подключении, он не записывается в `.env`. При первом подключении SSH также попросит подтвердить ключ сервера. Параметры `-VpsHost`, `-VpsUser`, `-VpsPort`, `-VpsPath` и `-SshKey` можно передать в команде, чтобы пропустить соответствующие вопросы.

Первый запуск создаст локальный `.env` из твоих ответов. Секрет API панели генерируется автоматически, пароль БД скрипт сам добавит в `DATABASE_URL`. Скрипт передаст текущие файлы и `.env` по SSH, установит Docker при необходимости, соберёт образы на VPS, запустит PostgreSQL, Discord-бота и панель, дождётся подключения к Discord. При повторном запуске сохранённые секреты используются снова. Пароль БД после первого запуска не меняй без отдельной миграции PostgreSQL.

После успешного запуска открой `http://IP_VPS:3000`, войди с `PANEL_PASSWORD`, затем открой **Valorant и роли**. ID двух ролей и голосового канала, а также времена правила задаются в панели. Если страница не открывается, разреши входящий TCP-порт `WEB_PORT` в настройках VPS-провайдера и файрволе сервера.

Для **повторного обновления** запусти ту же команду `powershell -ExecutionPolicy Bypass -File .\deploy-from-pc.ps1` из папки проекта. Скрипт возьмёт сохранённый локальный `.env`, передаст текущие файлы, пересоберёт нужные контейнеры и применит миграцию базы. Docker и зависимости системы повторно не устанавливаются, а данные PostgreSQL сохраняются. Параметры VPS нужно ввести снова или передать ключами `-VpsHost`, `-VpsUser`, `-VpsPort`, `-VpsPath` и `-SshKey`.

### Что писать в `.env`

Файл `.env` лежит рядом с `deploy-from-pc.ps1`. Строки начинаются с имени переменной, знака `=` и значения; кавычки вокруг значений не нужны. Токен и пароли никому не отправляй и в Git не добавляй.

| Переменная | Что вписать |
|---|---|
| `NODE_ENV` | Оставь `production`. |
| `POSTGRES_USER`, `POSTGRES_DB` | Оставь `dsbot`, если не меняешь имя пользователя и базы. |
| `POSTGRES_PASSWORD` | Придумай длинный пароль из латинских букв и цифр вместо `dsbot_password`. |
| `DATABASE_URL` | `postgresql://dsbot:ТВОЙ_ПАРОЛЬ@postgres:5432/dsbot?schema=public`; пароль должен точно совпадать с `POSTGRES_PASSWORD`. Для простоты используй в пароле буквы и цифры. |
| `DISCORD_TOKEN` | Токен из [Discord Developer Portal](https://discord.com/developers/applications) → приложение → **Bot**. Это секрет, не ID. |
| `DISCORD_CLIENT_ID` | **Application ID** из **General Information** того же приложения. |
| `DISCORD_GUILD_ID` | ID сервера: включи режим разработчика Discord, нажми правой кнопкой по значку сервера → **Копировать ID сервера**. |
| `VALORANT_ROLE_IDS` | Оставь пустым. Две роли выбери в панели **Valorant и роли**. |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Оставь пустыми: Telegram-бот не запускается. |
| `TELEGRAM_JOIN_PASSWORD` | Не используется при обычном деплое; можно оставить значение из примера. |
| `WEB_PORT` | Оставь `3000`, либо укажи свободный порт VPS. Адрес панели будет `http://IP_VPS:ПОРТ`. |
| `PANEL_PASSWORD` | Придумай пароль входа в панель вместо `admin`. |
| `PANEL_API_SECRET` | Придумай отдельный длинный случайный секрет вместо `change-me`. В PowerShell можно получить его командой `[guid]::NewGuid().ToString("N")`. |
| `RULES_EVAL_INTERVAL_MS` | Оставь `30000` — проверка обычных голосовых правил каждые 30 секунд. Правило Valorant проверяется отдельно каждые 15 секунд. |

Проверь, что в Discord Developer Portal → **Bot** включён **Presence Intent**; для других функций также нужны **Message Content Intent** и **Server Members Intent**. Пригласи бота на сервер с правами **Manage Roles** и **Move Members**, дай доступ к каналу назначения и поставь его роль выше двух выбранных ролей. На странице **Valorant и роли** есть инструкции по поиску ID.

### Если запускаешь прямо на VPS

Загрузи проект на VPS, затем выполни в папке проекта:

```bash
bash deploy.sh
```

Если `.env` отсутствует, скрипт создаст его и остановится. Заполни файл по таблице и повтори команду. Telegram-бот не запускается.

### VPS с диском 10 ГБ

Скрипт рассчитан на небольшой диск: образы собираются последовательно; бот получает только рабочие зависимости; логи каждого контейнера ограничены тремя файлами по 10 МБ; после запуска очищаются неиспользуемый кэш сборки и старые образы этого проекта. **Том PostgreSQL не удаляется.** На чистом минимальном VPS 10 ГБ должно хватить, если перед сборкой свободно несколько гигабайт; точный запас зависит от ОС и других программ. Скрипт проверяет диск и останавливается, если после очистки свободно меньше 3 ГБ. На заполненном VPS 10 ГБ гарантировать успешную сборку нельзя.

Проверка места на VPS:

```bash
df -h
sudo docker system df
```

Не запускай `docker compose down -v`: ключ `-v` удалит том базы данных.

Если деплой завершился с ошибкой, войди на VPS по SSH и посмотри логи из папки проекта:

```bash
cd ~/dsbot
sudo docker compose ps
sudo docker compose logs --tail=80 discord-bot
sudo docker compose logs --tail=80 web
```

## Настройка Discord-бота

При создании приложения в Discord Developer Portal включи:

- **Privileged Gateway Intents**: `SERVER MEMBERS`, `MESSAGE CONTENT`, `PRESENCE` (последний нужен для определения Valorant).
- **Bot Permissions**: `Read Messages`, `Send Messages`, `Use Slash Commands`, `View Channels`, `Manage Roles`, `Move Members`, `Connect`. Роль бота должна быть выше обеих снимаемых ролей в иерархии сервера.
- Пригласи бота на сервер через OAuth2 → URL Generator → scopes `bot` + `applications.commands`.

### Временное снятие ролей за Valorant в голосовом канале

Открой в панели страницу **Valorant и роли** (`/voice-penalty`), вставь ID двух ролей и канала назначения, укажи время первого наказания, дополнительные минуты для повторного наказания и время без ролей, затем включи правило. По умолчанию это 90, 20 и 20 минут: первое наказание через 90 минут, следующие через 110 минут после предыдущего. Для каждой пары людей в одном голосовом канале отсчитывается совместное пребывание. Если после порога хотя бы у одного Discord показывает активность Valorant, бот снимает у обоих выбранные роли, переносит их в указанный голосовой канал и позже возвращает только те роли, которые были у них до снятия. Если пара уже в этом канале, она остаётся там, но наказание и новый отсчёт работают. На время снятия ролей бот возвращает участника в канал наказания, если тот пытается перейти в другой голосовой канал; отключиться от голоса можно. Выход или самостоятельная смена канала сбрасывает повторный отсчёт: после нового входа снова действует первый порог. Проверка идёт каждые 15 секунд. Срок возврата ролей сохраняется в PostgreSQL и переживает перезапуск бота. Для определения игры нужен включённый `PRESENCE` intent и отображение активности у участника.

## Настройка Telegram-бота

1. Создай бота у @BotFather.
2. Добавь его в группу (права администратора нужны для чтения сообщений).
3. В группе бот попросит пароль — напиши значение `TELEGRAM_JOIN_PASSWORD`. Группа активируется, и сюда начнут приходить споры, награды и анонсы из Discord.

`TELEGRAM_CHAT_ID` больше не нужен — бот сам запоминает активированные группы (можно добавлять несколько).

```bash
npm install

# заполни .env и подними PostgreSQL (docker compose up -d postgres)
```

## Команды

**Discord (slash-команды):**
- `/stats [@user]` — статистика за месяц
- `/leaderboard` — топ активных
- `/dispute create <title> <options>` — создать спор
- `/dispute vote <id> <option>` — проголосовать
- `/dispute results <id>` — результаты
- `/rules` — список правил

**Telegram:**
- `/start`, `/stats`, `/leaderboard`, `/rules`
- Споры приходят с кнопками голосования.

## Как работают правила

Правило = триггер + условия + действия. Сейчас движок автоматически проверяет триггеры `voice` (голос) и `message` (сообщение). Проверка голоса идёт с интервалом `RULES_EVAL_INTERVAL_MS`. Триггеры `presence` и `cron` есть в типах проекта, но отдельно не запускаются. Правило **Valorant и роли** настраивается на своей странице панели и работает независимо от обычного редактора правил.

Условия:
- `users_in_voice` — определённые пользователи вместе в голосовом канале (операторы: все / хотя бы N / любой / никого)
- `user_in_voice` — пользователь в голосе
- `user_playing` — пользователь играет в игру
- `message_contains` — сообщение содержит слова
- `message_in_channel` — сообщение в канале
- `voice_users_count` — минимальное число людей в голосовом канале
- `user_voice_time` — накопленное время пользователя в голосе за день, неделю или месяц
- `user_messages` — число сообщений пользователя за день, неделю или месяц
- `weekday` — день недели
- `time_between` — время суток

Действия:
- `announce_discord` / `announce_telegram` — сообщение (с шаблонами `{users}`, `{game}`)
- `assign_game_tag` — пометить текущую голосовую сессию игрой (идёт в статистику)
- `give_points` — добавить очки
- `give_role` / `remove_role` — выдать или снять роль Discord
- `move_user` — переместить в голосовой канал
- `send_dm` — отправить личное сообщение Discord

Действия, отправляющие сообщение в Telegram, требуют отдельно запущенного Telegram-бота. `log_stat` пока не реализует запись метрики.

ID пользователей в условиях — это **Discord user ID** (правый клик по пользователю → Copy ID).

## Пинг-мост (Discord → Telegram)

Если кого-то пинганули в Discord, а он офлайн — в Telegram-группу придёт уведомление.

Настройка в панели → **Упоминания**:
- `Discord (ник / username / ID)` — кого сопоставляем (например `nikita` или Discord ID).
- `Telegram (@username или ID)` — как упоминать:
  - `@username` → просто текст-упоминание;
  - числовой Telegram ID → настоящее `@упоминание` с уведомлением (ID можно узнать у @userinfobot).

Если привязки нет — уведомление придёт текстом с Discord-ником.

## Формула рейтинга

`очки = минуты_в_голосе × вес_голоса + сообщения × вес_сообщения`

Веса настраиваются в панели → Настройки.

## Награды месяца

Автоматически считаются в последний день месяца в 23:00 (или вручную в панели → Награды → «Посчитать награды месяца»). Топ-3 получают награды с отображением в Discord, Telegram и на сайте.
